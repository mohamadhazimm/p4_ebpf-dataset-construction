# CIC-YNU-IoTMal check (2026-11-23)

Offline test of the thesis's host, network and hybrid detector designs on CIC-YNU-IoTMal
(Dadkhah et al., Information Systems 140, 102722, 2026, doi:10.1016/j.is.2026.102722). The detectors
were retrained inside the dataset. No VM, switch or Sink was used, no sample was run, and nothing was merged.

## Data

- Source: the dataset's processed tables, downloaded by the author into
  `external-datasets/cicynu/` (in the workspace, outside this repository) after CIC's download form. Only `strace.parquet` and
  `pcap.parquet` of each architecture (arm, mips, mipsel, x86) were used. `sar.parquet` was not used.
- The dataset ships no raw packets and no raw system-call timestamps or process IDs:
  - strace.parquet: counts over sliding windows of calls (window W, stride 1);
  - pcap.parquet: statistics per group of about 10 packets, in the CICIoT2023 style.
- Sandbox, from the public code (github.com/UNBCIC/CIC-YNU-IoTMal-Sandbox, read 2026-11-23):
  - one QEMU VM per sample, OpenWrt; x86 runs use `qemu-system-i386` with no KVM option, so software emulation;
  - 30-s runs; Internet access on by default;
  - benign samples generated by language models (dataset page).

## Method

`extract_cicynu.py` (SHA `f80569f7...`) does the following:

- It rebuilds each sample's exact call sequence from the window counts (differences of consecutive rows plus a
  forward fill per residue). There were 0 mismatched rows in 17,627 samples, with W per sample.
- Host features: the release's `features/host_model.py` signals over the whole trace (`h10_*`). Without timestamps
  there are no time windows. The same signals over 40 equal-count chunks (`hc_*`) are a pseudo-window variant.
- Network features: the dataset's own statistics, summarized with our five statistics (`net_*`). These are not the
  switch's 29 features, because there are no raw packets.

`protocol.json` (SHA `27cfe584...`) was written before any score. `eval_cicynu.py` (SHA `034b32ed...`) implements
it. Results are in `results.json` (SHA `cab57597...`) and `eval.log`.

- Detectors: RF500, balanced, seed 42, threshold 0.5. Concatenated hybrid; stacked hybrid with an inner 5-fold and
  a logistic regression. Activity baselines: log calls, log packets, and both.
- P1: random stratified 5-fold, fold seeds 42 and 0-3 (families seen).
- P2: leave one family out (Mirai, DarkNexus, Gafgyt, Generic), with benign in 4 buckets stratified by
  architecture.
- P3: leave one architecture out.
- R1 (host beyond activity): host minus the best activity baseline must be at least 0.05 in P2 (family mean) and in
  P3 (mean).
- R2 (fusion helps): the better hybrid minus the better single view must be at least 0.02 in at least 4 of 5 P1
  assignments, and at least 0.02 in P2.

## Population

17,627 executions with both views: 9,678 benign and 7,949 malware.

- Malware by family: Mirai 7,602 (96%), DarkNexus 225, Gafgyt 69, Generic 47, Tsunami 3, Agent 2, Rudedevil 1.
- Rows by architecture: arm 4,904, mips 4,308, mipsel 4,114, x86 4,301.
- 2,646 malware rows labeled "Unknown" exist only in the network table and were left out.

## Results (balanced accuracy; recall / specificity)

| detector | P1 random (5 assignments) | P2 family out (family mean) | P3 architecture out (mean) |
|---|---|---|---|
| host (whole trace) | 0.995 ± 0.000 | 0.910 (0.82 / 1.00) | 0.849 |
| host (40 chunks) | 0.975 | 0.874 | 0.819 |
| network | 0.960 ± 0.001 | 0.970 (0.96 / 0.98) | 0.921 |
| concatenated | 0.998 | **0.993** (0.99 / 1.00) | 0.880 |
| stacked | 0.999 | 0.951 (0.90 / 1.00) | 0.885 |
| activity: calls | 0.818 | 0.668 | 0.664 |
| activity: packets | 0.862 | 0.881 | 0.882 |
| activity: both | 0.965 | 0.898 | 0.814 |

P2 by held-out family (host / network / concatenated / stacked):

- Mirai (training then has only 347 non-Mirai malware): 0.866 / 0.944 / 0.973 / 0.985.
- DarkNexus: 0.818 / 0.957 / 0.999 / 0.819. The stacked hybrid follows the host view here (recall 0.64).
- Gafgyt: 0.990 / 0.989 / 1.000 / 1.000.
- Generic: 0.967 / 0.989 / 1.000 / 1.000.

P3, ARM held out: every detector fails (host 0.487, specificity 0.07; network 0.688; concatenated 0.522; stacked
0.549). MIPS, MIPSEL and x86 held out: 0.92-1.00.

Decision rules:

- R1 not met: host minus activity is +0.013 in P2 and −0.032 in P3.
- R2 not met: the P1 gains are +0.004 in each assignment, because the single views are already at 0.995. The P2
  gain is +0.023 (concatenated 0.993 vs network 0.970).

Most important features (full-data forests):

- host: entropy, distinct calls in the first 50, top-call share;
- network: Telnet and SYN statistics (Mirai's telnet scanning).

## Reading

- With families seen the task is easy. Call and packet volume alone reach 0.965, so the near-perfect P1 scores
  measure little.
- On held-out families the concatenated hybrid is the best detector, 0.023 above the network view and 0.083 above
  the host view. The stacked hybrid is unstable: it collapses to the host view on DarkNexus. This is the same
  pattern the thesis reports for learned fusion.
- The host features barely beat volume (R1). The whole-trace host signals are coarser than the thesis's 0.5-s
  windows.
- No detector transfers to a held-out architecture when ARM is the target. The cause was not established; the ARM
  window encoding differs (W = 4 or 16 for many samples).

## Limits

- Mirai is 96% of the malware.
- The benign programs were written by language models.
- The network view is the dataset's statistics, not the switch's features.
- The host view is whole-trace.
- The sandbox had Internet access by default.
- The P1, P2 and P3 folds are not grouped by sample lineage.
- Reported in the thesis (Ch6 §6.9.5, plus mentions in the abstract, Ch1, Ch5, Ch7; numbers in thesis
  `data/lab/cicynu.json`, written by `export_thesis_json.py`) and in the journal (§5.4, §7.4, conclusion).
